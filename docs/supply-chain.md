Both Dockerfiles use these immutable digests. The proxy image removes the
upstream binary's unnecessary bind capability and explicitly owns its private
certificate/config directories before switching to UID 10001. CI builds and
runs it under the same read-only/capability restrictions as deployment.

The `requirements*.txt` locks were generated by pip's resolver on a GitHub Linux
amd64 / CPython 3.12 runner using PyPI download metadata. They include exact
transitive versions and the selected wheel's SHA256. Production/test/optional
scraper locks share the same runtime versions. Installation requires hashes;
unsupported architectures must generate and review their own compatible locks.

The lock-resolution workflow is manual and read-only: it uploads proposed locks
for a maintainer to review and commit. It does not update the repository by
itself. Package, secret, and image scans run independently of lock generation.

Trusted push/manual CI jobs may create bounded diagnostic check reports using
`checks:write`; they cannot write repository contents. The reporter restricts
repository, branch, event, API host, and head SHA and omits matched secret values.
Pull-request/fork events never publish through that helper. CodeQL alone has the
additional `security-events:write` scope required to upload its analysis.
