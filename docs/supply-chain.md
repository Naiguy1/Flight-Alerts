The first image scan rejected the earlier Python slim/stock Caddy images because
of high-severity OS and Go dependency findings. Those images are no longer build
inputs. `Dockerfile.proxy` rebuilds the fixed
[Caddy v2.11.7 module](https://github.com/caddyserver/caddy/tree/v2.11.7) with
[x/net v0.60.0](https://github.com/golang/net/tree/v0.60.0) and Go 1.27.3. Go module
downloads are verified through the public checksum database, and `go mod verify`
runs before a read-only build. The compiled static binary carries its module
version information for image scanning; runtime package metadata is not removed
to conceal findings. The runtime contains certificates/timezone data and no
upstream privileged-port file capability. Private directories are owned before
switching to UID 10001. CI exercises the actual read-only/capability restrictions.

The Python locks were generated by pip's resolver on a GitHub Linux amd64 /
CPython 3.12 runner using PyPI download metadata. Supplementary musllinux wheel
hashes were obtained from actual downloaded wheels for the **same exact versions**.
The locks retain both glibc and musl wheel hashes for their supported CPython 3.12
Linux amd64 target. Production/test/optional scraper locks share runtime versions.
Installation requires hashes and binary wheels; other architectures/interpreters
must generate and review their own compatible locks. A successful pin/hash check
is not a replacement for the actual package/image vulnerability gates.

The lock-resolution workflow is manual and read-only: it uploads proposed locks
for a maintainer to review and commit. It does not update the repository by
itself. Package, secret, and image scans run independently of lock generation.

Trusted push/manual CI jobs may create bounded diagnostic check reports using
`checks:write`; they cannot write repository contents. The reporter restricts
repository, branch, event, API host, and head SHA and omits matched secret values.
Fork/untrusted PR events never publish through that helper. Only synthetic test
diagnostics from the exact same-repository production-hardening-to-main PR may
create a separately named PR Tests report, bound to the verified PR head SHA.
CodeQL alone has the
additional `security-events:write` scope required to upload its analysis.

The Image job also validates the CycloneDX SBOM has a usable package inventory.
Its connector-readable report includes package names/versions, the SBOM file's
SHA256 and all image vulnerability severity counts, including lower severities.
Missing/malformed inventory fails the gate. The full `image-sbom` artifact remains
available for review; only bounded package identifiers, never arbitrary SBOM
properties, scanner paths or matched secret contents, are published in diagnostics.
